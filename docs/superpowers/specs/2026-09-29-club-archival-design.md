# 社团归档设计（#70）

日期：2026-09-29。经确认，归档后历史资料仅管理员可查看；原社长和成员不再有历史读取权限。通知属于 #69，本次不做前端解散入口。

## 目标与方案选择

社长可以解散正常运营的社团。保留 `Club`、成员、活动、签到和审核数据，只把既有 `Club.status` 从 `normal` 变为 `archived`，不加列、不硬删除。仅隐藏公开页面不足以阻止通过 API 读取或继续写入；硬删除又会破坏管理员需要保留的历史。因此采用有权限边界和并发保护的状态迁移。

## API 与权限

- `POST /api/v1/clubs/{club_id}/archive` 不接收请求体，成功返回 `204`。复用 `ClubRoleChecker([president])`，保留 `AccessPolicy` 对 admin/dev 的既有绕过；副社长、普通成员、其他社团社长和匿名用户不能调用。不存在返回既有 `CLUB_NOT_FOUND`；正常社团首次归档；已归档的同一授权调用返回 204，不改动任何数据；`unreviewed` 返回结构化 `403 CLUB_NOT_ACTIVE`，不能以归档代替撤回创建申请。204 不回传归档后的历史资料。
- 公开社团列表/refs 已过滤 `normal`，公开详情维持非正常社团不可读；公开活动列表与 refs 补上相同的状态检查。`/users/me/clubs/` 在组装摘要前过滤 archived，包括成员关系和待处理入社申请。原负责人也不能通过 `/clubs/{id}/manage`、签到名单、待审核成员名单、社团活动及其它按社团 ID 的成员路由读取归档资料。社团级角色检查对已归档社团拒绝非 admin/dev；归档端点为幂等调用提供明确例外。未授权读取不序列化关联数据。
- 管理员仍可通过现有 `/admin/clubs/` 列表和 `/admin/clubs/{id}` 详情读取已归档数据；按既有后台权限 admin/dev 可读取归档活动的签到名单。归档后的管理员权限仅限读取历史，不允许通过通用后台 PATCH 修改或复活归档社团。
- 后台通用 PATCH 的 `status=archived` 返回结构化冲突，管理员要归档也走专用归档事务。对归档记录的 PATCH、`archived -> normal/unreviewed` 均拒绝，避免绕过下述清理和锁语义。其余既有后台状态操作保持原样。

## 事务、不变量和待处理申请

归档事务先获取社团行的 `FOR UPDATE` 锁，在锁内重新检查状态和权限，再设置 `archived`。正常社团归档时，同一事务把仍为 pending 的社团资料修改、活动创建及活动修改申请标记为 `superseded`；已审核记录不变。待处理入社和认领申请保持历史行，但归档后不能列给原负责人或被批准；不伪造审核员/验证员身份。若任一步失败，状态和申请的改动全部回滚。

为了保证“归档提交以后不能再发布活动、修改资料、加入成员或签到”，会改变社团自身或其历史数据的写路径在一个事务内统一先锁社团并确认 `normal`，再锁活动/申请等子记录并进行最终校验及写入。覆盖社团资料修改及审核、成员角色/退社/入社/认领及验证、活动创建与修改及其审核、手工/扫码签到、社团综评记录、联合活动的社团参与写入、星级申请和管理员/社联对社团的编辑。审核端可先无锁读取申请所指的社团 ID，再按社团→申请/活动顺序加锁和刷新申请状态；不得以“申请已锁→等待社团锁”与归档相反的顺序运行。正在归档时的另一写入要么先提交、被归档事务看到，要么等待后因非 normal 被拒。既有活动取消 PR #148 若尚未合并，本分支不复制其实现；合并/重基后应维持社团锁先于活动锁并补交叉回归测试。

普通写接口继续使用既有 `CLUB_NOT_ACTIVE` 等错误码。历史行只读，唯一约束中 `status != archived` 的既有部分索引允许之后创建同名新社团，但不会复活旧 ID。

## 验证与边界

- HTTP 测试覆盖社长/admin 的归档与重复调用、其他身份拒绝、unreviewed/不存在的处理、归档后公开和成员读取不可见、后台详情可见、后台 PATCH 不能复活或修改。
- 测试 pending 审核申请被作废，历史成员/活动/签到仍在数据库中；逐类验证归档后上述写接口拒绝。独立 PostgreSQL session 的确定性并发测试覆盖归档与审核批准、活动创建或签到的锁序和最终状态，不用 sleep 作为正确性判据。
- 跑完整后端测试、Ruff、格式、mypy、OpenAPI 相关检查；如改动生成的接口类型，仅纳入本端点相关差异。检查迁移头（本次无迁移）与现有开放 PR 的重叠，再开引用 #70 的独立 PR，不合并。
